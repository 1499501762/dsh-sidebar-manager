# 实现细节 / Internals

## 它做三件事

### 1. 布局守卫（修「侧边栏炸了」）

左侧边栏是固定高度的 flex 列，中间的 `regionArea`（工作区 / 会话树）是 `flex:1` 且 `min-height:0`。
上方入口 + 下方底部一旦超窗口高度，flex 会先把会话树压成 **0 高**——会话列表直接消失，底部还会溢出屏幕。

插件注入的规则：

| 规则 | 作用 |
| --- | --- |
| `regionArea { min-height: 50vh }` | 会话树保底 = **窗口高度的一半**（设置项可改，见下） |
| 面板列表可收缩 + 滚动 | 放不下时自己滚，不去挤会话树（底部有余量时给渐隐提示） |
| 底部动作横排 | 底部动作不再一条占一整行 |
| 还原 `footArea` 纵向布局 | 抵消 `@linxin666/dsh-remote-web-ui` 注入的全局 footer 覆盖（它假设了另一套 footer DOM） |
| 只在展开态生效 | 侧边栏收起成 56px 轨道时，交还给 shell 自己的规则 |

### 1b. 工作区最小高度（设置项）

「其他」卡片里可以改：默认 `50vh`（窗口一半），填像素值即固定；填 0 / 清空恢复默认。
数值超过当前窗口能承受的上限时会**自动收敛**（提示里显示上限），避免把底部顶出屏幕；窗口缩放时会重新计算。

### 2. 老入口 → 全局面板（adoption）

`原料价格 / 汇率 / 项目看板 / 订单看板 / 日历 / Thunderbird` 这几个是自写的老版本插件：
它们直接往侧边栏根节点插一行 `<button>`，点开时把一块绝对定位的看板盖在中间栏上。那套接缝没有 slot，
既不能和 shell 自带面板一起排序，也不能被 shell 隐藏。

本插件把它们**提升成真正的全局面板**：

- 注册一条 `sidebar.panellist`（图标直接复用原行里的 SVG）→ 出现在全局面板列表里；
- 注册一个 keyed 的 `main` 面板 → 挂载时点一下被隐藏的原始行把看板打开，卸载时派发
  `dsh-panel-activate` 让看板自己关掉；
- 原始行仍留在 DOM 里（隐藏），因为那几个插件会不断把行重新插回去，这里不改它们一行代码。

看板自己的 × 关闭后，插件会把 shell 送回对话（不会留一个空白面板）。

### 3. 侧边栏管理（设置 → 侧边栏）

侧边栏的面板列表由本插件重新渲染（原生列表隐藏，行是原生按钮的**克隆**，样式 / 图标 / 文字完全一致，
点击转发给原按钮），所以可以任意排序、隐藏、折叠进自定义分组。

设置页是一个**菜单编辑器**：

- 每行：`图标 + 名称`，右侧是类型徽标（`全局面板` / `已隐藏`）和悬停出现的 `⋯`。
- `⋯` 弹出浮动操作菜单：`上移` / `下移` / `移入分组 ▸`（二级菜单再向右展开，列出所有分组 + 移出分组）/ `隐藏`。
- 分组行：左侧 `▸`，右侧 `分组 · N`；悬停或点击 `▸`（也可以双击行）展开右侧浮层，列出组内条目，
  每条可以再点 `⋯` 单独操作。
- `＋ 新建分组`：建一个空分组并直接进入重命名（回车确认 / Esc 取消）。
- 分组删除后，组内条目自动回到顶层列表。
- 配置存在 localStorage（`dsh-sidebar-manager:v2`），刷新 / 重启都在；旧版 v1 配置会自动迁移。

侧边栏里的分组行：`▤ 分组名 N ▸`，悬停或点击就在右侧弹出浮层，列出组内入口（带图标），点一下即打开对应面板。

`其他` 卡片里还有 **工作区最小高度**、**实验性：允许跨区搬移** 和 **恢复默认**。

### 4. 顶部工具栏 / 顶栏（存在时才接入，支持分组与向下浮层）

DSH Desktop / 新版本 shell 在会话标题栏右侧有一排工具栏，它们来自 `conversation.session.header.actions`
这个 **list slot**（`id` 由各插件注册，插件拿不到 DOM 的 session 数据也一样能管）。

插件会自动探测：

- 容器不存在（老版本 / 公版 shell 没这排按钮）→ 什么都不做，设置页也不显示这张卡片；
- 容器存在 → 设置页出现 **顶部工具栏** 卡片，列出当前实际渲染的每个组件（智能体团队 / 创造模式 / 撤销·快照 …），
  和侧边栏一样支持 `上移 / 下移 / 移入分组 / 隐藏 / 新建分组`（菜单编辑器）；
- 分组在真正的顶栏里渲染成一个 `▤ 名称 N ▾` 按钮，**向下展开浮层**列出组内条目（顶栏是横向的，所以和侧边栏的向右浮层方向相反）；
- key 优先用组件自己的 `data-*` 标记（如 `data-undo-header`），其次 slot id，最后才是文案，
  因此换语言不会丢配置。

实现是「CSS `order` + `display:none`」，**不接管** 那排 DOM（它是 React 渲染的，克隆会丢内部状态）。

### 5. 跨区搬移（实验性开关，默认关闭）

「其他」卡片里有独立的「实验性功能」分区，勾选 **允许跨区搬移（顶栏 ↔ 侧边栏）** 后，条目行的 ⋯ 菜单多出：

- 顶栏组件 → **移到侧边栏**：侧边栏出现一行 `⇡ 名称 [顶栏]`，点它会触发该组件的主操作；组件本身在顶栏隐藏；
- 侧边栏入口 → **移到顶栏**：顶栏多出一个同款按钮（图标+文字），点它直接打开原来的面板；侧边栏那一行消失。

实现上：侧边栏 → 顶栏是**克隆转发**（点一下等于点原按钮）；顶栏 → 侧边栏是**代理行**（点一下等于触发组件主按钮）。
没有真的把 React 节点搬走——那是唯一能让复合控件（撤销/快照那种一簇按钮）在别处还活着的方式，但会随它的容器查询/状态一起抽风，所以用代理更稳。

关掉开关：所有摆放立即还原到各自原位（配置里的跨区记录保留，再打开就恢复上次摆法）。
注意：当中间区域显示的是某个全局面板（不是对话）时，顶栏这一排本来就不存在，此时顶部工具栏卡片会自动隐藏。

### 6. 分组的其他能力

- **自定义图标**：分组行的 ⋯ → `设置图标`，填 emoji 或一两个字符（留空回到默认 ▤）。侧边栏分组行、顶栏分组按钮都用这个图标。
- **展开查看**：分组行左侧的 `▸` 点一下展开子项，子项直接作为行显示（缩进），可以继续拖动；`↩` 把子项移回顶层。
- **拖拽**：所有行都可以拖。拖到另一行的上半/下半 = 插到它前面/后面；拖到分组名上 = 归进该分组；把分组里的子项拖到顶层行上 = 移出分组。拖动时有蓝色插入线和分组高亮。

### 7. 图标选择器（分组 + 每个条目）

**分组**和**每个侧边栏条目**都能换图标：行左侧的图标本身就是按钮，点它弹出选择器：**24 个线性图标**（24×24、stroke=currentColor，和界面自带图标同一套观感），
外加「粘贴 SVG / 应用 SVG / 让 Agent 生成一个 / 上传图片 / 恢复默认」。

- 图标编码：`svg:<内置id>`、`svgdata:<净化后的 SVG 片段>`、图片则是 32×32 PNG DataURL；老数据里的字形仍然照常显示。
- 粘贴的 SVG 走白名单净化：只允许 path/circle/rect/line/polyline/polygon/ellipse/g 与一组绘图属性，
  脚本、事件、外链、style 全部剔除；不是合法 SVG 直接判红不落盘。
- 「让 Agent 生成一个」把一段带约束的提示词复制到剪贴板并填进输入框，Agent 画好回你一段 `<svg>`，粘贴 → 应用即可。

### 8. 插件挂在 region 顶部的入口（MCP 连接器之类）

有些插件不通过 `sidebar.panellist`，而是往 region 区顶部插一行（`div[data-mcp-connector-top-mount]`）。
这些行现在也会被收进列表统一管理：原挂载点隐藏，管理列表里出现同名同图标的一行，顺序/分组/隐藏都和普通入口一样。

### 9. Agent 接口 + 技能

页面里暴露 `window.__dshSidebarManager`：

```js
__dshSidebarManager.entries()                       // [{key,label,kind,pool}]
__dshSidebarManager.state()                         // {sidebar, header, config, aggressive}
__dshSidebarManager.move(key, {pool, groupId, index})
__dshSidebarManager.addGroup('sidebar', '常用', '📁')
__dshSidebarManager.setHidden(key, true)            // false 恢复
__dshSidebarManager.setGroupIcon('header', id, '🚀')
__dshSidebarManager.setLayout('sidebar', [...])     // 整棵树
__dshSidebarManager.reset()
```

配套技能 `sidebar-manager`（`%APPDATA%\dsh-desktop\harness\skills\sidebar-manager\SKILL.md`）写清了调用姿势与验证流程。

### 10. 代理都代理了什么

| 交互 | 是否代理 |
| --- | --- |
| 左键点击 | ✅ 转发到原控件的点击 |
| 悬浮（鼠标移入/移出） | ✅ 补发 `mouseover/mouseenter`、`mouseout/mouseleave`（JS 悬停逻辑可用；纯 CSS `:hover` 无法伪造） |
| 右键 | ✅ 拦截代理元素的 `contextmenu`，在原控件位置补发 |
| 中键 | ✅ `auxclick` 转发点击 |
| 键盘 Enter/Space | ✅ 代理行支持 |
| 拖拽、焦点、快捷键 | ❌ 不代理 |

多按钮组件（顶栏「撤销」那一簇）代理后是**逐按钮可点**的：悬浮代理行会列出它探测到的全部按钮
（撤销上一步 / 重做 / 立即创建快照 / 对话级撤回 / 快照管理），每条都能单独触发。

### 11. 老插件入口的存活修复

那 6 个早期自写插件（原料价格 / 汇率 / 项目看板 / 订单看板 / 日历 / Thunderbird）是靠"旧按钮 → 注册为全局面板"的桥接接进来的。
以前侧边栏一刷新，宿主会把我们注入的 slot 注册丢掉，而旧的代码只在首次登记一次，于是入口就永久消失。

现在每轮巡检（含 3s 看门狗，DOM 没变化也会跑）都做三件事：

1. **重新绑定**：宿主重建了旧按钮时，把记录指向新节点并重新打标记；
2. **补齐注册**：`sidebar.panellist` 里找不到我们那条时重新注册（旧句柄先释放，且列表为空时不乱重建，避免抖动）。

点击时还会再找一次活节点（`resolveAdoptedElement`），节点被换掉也能打开原面板。

3. **不再自废武功**：以前 `slots.inject` 抛一次就把 `slotCtx` 置空、从此永不重试——这就是"掉了就再也不回来"的真凶；现在只做退避重试。

排查用：`__dshSidebarManager.diagnostics()` → `[{id,key,label,elementConnected,registered}]`，
`__dshSidebarManager.bridge()` → `{slotContext, adopted, retryAt}`；全绿才算桥接健康。

条目的自定义图标存在 `config.icons[key]`（key 就用 `entries()` 里的那个），列表重绘时覆盖掉宿主自带图标；
清空即恢复原图标。Agent 可直接调 `__dshSidebarManager.setEntryIcon(key, "svg:chart")`。

## 实现要点

- **不搬动 React 节点**：面板列表由本插件用「原生按钮克隆」重建，React 的 children 一个没动；
  选中态通过读原按钮的 `aria-current` / `panelActive` 类镜像到克隆行。
- **不认构建哈希**：shell 自己的行靠 `[class*=newSession]` 这类稳定后缀识别，其余直接子按钮都当插件注入行处理。
- **面板 key 用 slot id**（`panel:ssh`、`panel:dsm-qe-...`），不是文案，所以文案变化不会丢配置；
  `ctx.slots.entriesOfSlot("sidebar.panellist")` 取不到时退回按名字匹配。
- **合并布局**：配置里只存「用户排过的」；新插件新增的条目自动追加到末尾，删除的自动剔除。
- 设置页走 `settings.section` slot，和「通用设置 / 模型 / 内置插件」同级。
- 顶部工具栏走 `conversation.session.header.actions` 列表的 DOM：只调 `order` / 隐藏，不重建节点；
  slot 不存在时整块能力自动消失（这是给公共仓库版本准备的行为）。

## 安装 / 卸载

已装在当前 desktop 配置（`%APPDATA%\dsh-desktop\harness\profiles\web`）：

```bash
pwsh -File scripts/install.ps1     # 幂等：建 junction + 往 cordis.patch.yml 追加 insert 行
pwsh -File scripts/uninstall.ps1   # 移除（源码目录不动）
```

> 插件市场执行 `pnpm install` 时可能清掉不在 profile `package.json` 里的 `node_modules` 目录。
> 如果某次市场更新后插件消失（侧边栏又挤回去），重跑一次 `scripts/install.ps1`。

## 已知取舍

- 设置页用「菜单 + 二级浮层」而不是拖拽（按选定的交互实现），排序靠 `上移 / 下移`。
- 克隆行的选中态是「读原按钮后镜像」，点击后约 60ms 内同步，正常情况下不可感知。
- 侧边栏里分组浮层的位置相对分组行实时计算，窗口极窄时会自动贴边。
